Repository cache coverage and size

Packages from the current index found on disk, including shared copies. This scans the cache only when requested. It measures file presence, not freshness or signature validity, and includes packages outside the warm list. Physical and available sizes are calculated from the same scan.

Redundant dedup copies

Remove obsolete physical copies only when the current shared copy is present. Cleanup also runs hourly in bounded batches. Requires dedup, purge and cache probing. Warmed records are preserved.

Orphaned repositories

SQL bookkeeping (snapshots, history, warmed/ban state, Nix artifacts, failure streaks) left over from a repository no longer in config.yaml — for example after a delete, or an id rename (delete + add). This never touches physical cache files on disk, only these rows.

Zombie packages

Packages tracked as warmed but already replaced or removed from the current index across every repository — e.g. an old version superseded by a new one under a different key. These can never be requested again under their old key, so they're usually safe to purge right away rather than waiting out the normal warmed-package retention window. Requires nginx.enable_purge.
